# Agent guidance

Read README.md and CONTRIBUTING.md before changing the project. Keep one runnable `durop` binary and respect the workspace boundaries in [docs/architecture.md](docs/architecture.md): domain libraries must not depend on the application or Bevy. Put interchangeable behavior behind the catalog/controller/media contracts and test those contracts. Use typestate for meaningful lifecycle transitions; preserve runtime checks for external failures. Preserve lockfiles and run the relevant workspace checks. Do not mutate Git configuration or install hooks implicitly.

Document symbols where they are declared: public APIs need rustdoc explaining their contract, and private types/helpers need purpose or invariant comments. Separate declarations, implementations and functions with blank lines. Associate behavior with its owning type where reasonable; Bevy systems, FFI callbacks and genuinely ownerless utilities may remain free functions. Follow the issue hierarchy and priority conventions in [docs/planning.md](docs/planning.md).

Use Conventional Commit headers for every new non-merge commit and every pull request title: `type(scope)!: description`, with scope and `!` optional. Follow the supported types, examples, and validation command in [CONTRIBUTING.md](CONTRIBUTING.md#commit-and-pull-request-titles). CI checks PR titles; it does not validate individual commits or legacy history. Preserve existing history rather than rewriting it to apply this policy retroactively. Autogenerated merge commit subjects are exempt.
